## Problem
1. "add a fable specific usage if you can": the Claude card shows 5h and 7d but not the
   model-scoped weekly limit the endpoint now reports for Fable.
2. "handle multiple claude accounts, personal max and work enterprise": one Claude ring reads
   one credentials file. Zac has two logins.
3. "if I click on a dev server I want to be taken there if it's a web ui and if it's not a

## Desired outcome
- Claude card lists every window in the `limits` array, so "7d Fable" appears at 5 percent.
- One Claude ring per logged-in account, titled by plan ("Claude Max", "Claude Enterprise").
- Dev Servers rows carry a kind tag (web, api, postgres, redis, tcp). Web and api rows open
  in the default browser on click; the rest are labelled and inert.

- Claude Code keeps one credentials file per config directory (`CLAUDE_CONFIG_DIR`). Accounts
  are discovered as directories, never by copying tokens.
- Probing a port must be cheap, once per server, with a short timeout, and never block sampling.
- Read-only remains; opening a URL is the only outward action, and only on a click.
