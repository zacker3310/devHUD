# Spec: server actions

**id:** T4   **intent:** .buildloop/intent/T4.md
**status:** accepted

## Requirements
R1. `ServerCommand` (pure): `shellQuote`, `relaunchScript(argv:cwd:log:)` producing
    `cd <cwd> && nohup <argv> </dev/null >>log 2>&1 &`, `logURL(for:)` under
    `~/Library/Logs/devHUD/<name>-<port>.log`.
R2. `ServerActions` (@MainActor @Observable): `openEditor`, `openTerminal`, `requestKill`,
    `cancelKill`, `confirmKill`, `restart`; `pending[id]` is `.confirmKill(until:)`,
    `.killing`, `.restarting`, `.failed(String)`.
R3. Kill: SIGTERM, wait up to 3 s polling `kill(pid, 0)`, then SIGKILL, then resample.
R4. Restart: read argv with `ps -ww -o args= -p pid` and cwd before killing; after the
    pid is gone, run `/bin/zsh -lc <relaunchScript>`; resample after 1 s. Missing cwd or
    argv -> `.failed`.
R5. Editor: `open -a <editorApp> <cwd>`, `editorApp` UserDefault, default
    "Visual Studio Code". Terminal: `open -a Terminal <cwd>`. Both disabled without a cwd.
R6. Row UI: on hover a trailing strip of four icon buttons replaces the metrics; kill turns
    the row into "Kill <name>?  Kill  Cancel" until confirmed, cancelled, or 5 s pass.
    In-flight and failed states render as the row subtitle.

## Acceptance criteria
AC1. build + tests green | CHECK:build, CHECK:tests
AC2. `relaunchScript` quoting survives spaces and quotes | CHECK:tests
AC3. live: kill a throwaway http.server through the DEBUG hook and see it leave the list | CHECK:live-kill
AC4. live: restart the same server and see the new pid in the list | CHECK:live-restart

## Ordering surface
concurrency: one in-flight action per server id, tracked in `pending`; the
sample loop keeps running and may drop the row mid-action. `pending` entries
for ids no longer listed are pruned by the card.
