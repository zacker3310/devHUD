# Spec: Fable window, multi-account Claude, server kinds

**id:** T3   **intent:** .buildloop/intent/T3.md
**policies applied:** T1/T2 conventions
**status:** accepted

## Requirements
R1. `ClaudeUsageDecoder` prefers the `limits` array: session -> "5h", weekly_all -> "7d",
    weekly_scoped -> "7d <scope.model.display_name>" (Fable), else kind. Flat keys are the fallback.
R2. `ProviderSlot { id, kind, title }` identifies a provider instance. `UsageProvider.slot`.
    Stores, selection and rows are keyed by slot, `ProviderID` stays the kind (color, mark).
R3. Claude config directories: `claudeConfigDirs` (UserDefaults, array of paths) if set; else
    `$CLAUDE_CONFIG_DIR` if set, `~/.claude`, and every `~/.claude-*` or `~/.claude_*`
    directory holding `.credentials.json`. Default directory first. Title is
    "Claude <SubscriptionType>" from the credentials file, falling back to the directory name.
R4. Pill rows are `HUDState.rows`: one per provider slot then the servers badge. Geometry and
    hover resolution take the row list; nothing static assumes three providers.
R5. `ServerKind`: web, api, service(name), tcp, unknown. Known commands map without probing
    (postgres, redis-server, mysqld, mongod, sshd, ollama -> api). Portless-managed -> web.
    Otherwise one GET `http://127.0.0.1:<port>/` with a 1.5 s timeout: text/html -> web,
    any other HTTP response -> api, cannot connect or timeout -> unknown (retry next sample),
    any other URLError -> tcp.
R6. Probing runs off the main actor, at most once in flight per server id, results cached by
    server id for the process lifetime.
R7. Dev Servers rows show the kind as a chip. Rows of kind web or api show an open arrow and
    open `http://<portless host>` or `http://localhost:<port>` in the default browser on click.
    The card panel accepts first mouse.

## Acceptance criteria
AC1. build + tests green | CHECK:build, CHECK:tests
AC2. Claude card shows "7d Fable" with a percent | CHECK:live-fable
AC3. a second config dir with credentials yields a second Claude ring | CHECK:discovery (unit test on the pure discovery function; no second login on this machine)
AC4. Dev Servers rows carry chips; the 4173 http.server row is "web" | CHECK:live-kinds
AC5. classification is unit tested for html, json, connect-refused, parse error | CHECK:tests

## Ordering surface
concurrency: probe tasks write back into the PortsStore on the main actor keyed by id; the
sample loop reads the cache. Single writer per key, no ordering to check.

## Rejected alternatives
- One Claude ring with both accounts in the card: not glanceable, and the ring percent would be ambiguous.
- Copying work credentials into the app: never.
